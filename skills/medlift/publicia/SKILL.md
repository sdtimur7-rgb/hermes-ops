# Publicia — платформа публикации статей

Publicia — платформа MEDLIFT: врачи публикуют научные статьи в журналах для
периодической аккредитации. Продажами и поддержкой занимаются ИИ-агенты внутри
платформы.

**Главное правило: на любой вопрос про Publicia, продажи, сделки, наборы статей
или базу знаний — сначала запроси API, потом отвечай.** Никогда не отвечай по
памяти и не выдумывай цифры: они меняются каждый день.

## Доступ

Токен лежит в `PUBLICIA_SERVICE_TOKEN` (файл `~/.hermes/.env`).
База: `https://publicia.ru/api/service/v1`

```bash
curl -s -H "Authorization: Bearer $PUBLICIA_SERVICE_TOKEN" \
     -H "Accept: application/json" \
     "https://publicia.ru/api/service/v1/metrics" | jq .
```

Данные приходят **обезличенными**: вместо имён и контактов — псевдонимы. Это
нормально, так задумано (152-ФЗ). Не пытайся деанонимизировать клиентов.

## Что можно читать

| Эндпоинт | Что отдаёт |
|---|---|
| `GET /health` | жив ли токен и какие у него права |
| `GET /metrics` | сводка: лиды, сделки, оплаты, выручка, средний чек, конверсия, воронка |
| `GET /deals` | список сделок |
| `GET /deals/{id}` | одна сделка с историей диалога |
| `GET /listings` | открытые наборы статей: направления, свободные места, сроки, индексация |
| `GET /knowledge` | статьи базы знаний (продажи и поддержка) |
| `GET /templates` | шаблоны ответов ИИ-продавца |
| `GET /proposals` | статусы присланных предложений — что человек решил |

## Что можно писать

| Эндпоинт | Что делает | Осторожность |
|---|---|---|
| `POST /notes` | внутренняя заметка в сделку | клиенту **не** уходит, безопасно |
| `POST /tasks` | задача менеджеру | создаёт работу человеку — по делу |
| `POST /drafts/knowledge` | черновик статьи БЗ | неопубликованный, безопасно |
| `POST /drafts/templates` | предложить шаблон ответа | попадает в очередь «Предложения ИИ» на утверждение |
| `POST /proposals` | пачка предложений по улучшению ИИ | требует доказательств, см. ниже |
| `POST /exports` | заказать обезличенную выгрузку (ZIP с JSONL) | тяжёлая операция |

**Ничего из этого не отправляется клиентам напрямую.** Любое изменение,
влияющее на живые продажи, проходит через утверждение человеком в админке.

## Как отвечать на типовые вопросы

«Как дела с продажами?» / «Сколько продаж?»

```bash
curl -s -H "Authorization: Bearer $PUBLICIA_SERVICE_TOKEN" \
     "https://publicia.ru/api/service/v1/metrics" | jq '.kpis, .funnel'
```

Отвечай цифрами из `kpis`: `leads`, `deals`, `paid`, `revenue`, `avgCheck`,
`conversion`, `lost`. Поля `prev*` и `*Delta` — сравнение с прошлым периодом;
если `prev` равно нулю, значит данных за прошлый период нет, и говорить о
динамике нельзя — так и скажи, не выдумывай тренд.

«Какие статьи сейчас доступны?» / «Что можно предложить клиенту?»

```bash
curl -s -H "Authorization: Bearer $PUBLICIA_SERVICE_TOKEN" \
     "https://publicia.ru/api/service/v1/listings" | jq '.listings[] | {title, directionLabels, indexing, freeSeats, sendBy}'
```

Важны `freeSeats` (свободные места) и `sendBy` (срок сдачи) — именно они
определяют, что реально можно продать сегодня.

«Почему просели продажи?» — сначала `metrics` за период, затем `deals`
для выборки, и только потом выводы. Не строй гипотезы на пустом месте.

## Правила

1. **Сначала данные, потом ответ.** Цифры только из API.
2. **Не выдумывай динамику**, если `prev`-показатели нулевые.
3. **Не деанонимизируй** клиентов — данные обезличены намеренно.
4. **Записи — по делу.** `POST /tasks` создаёт работу живому менеджеру;
   не создавай задачи ради активности.
5. **Предложения по улучшению ИИ** (`POST /proposals`) обязаны содержать
   доказательства: id сделок, цитаты, метрики. Без них они бесполезны.
6. **Токен не разглашай** — ни в ответах, ни в логах.
